> 更新日期：2026-08-26
> 当前阶段：数据体系已建立，准备进入 Gold 标注与 Baseline 训练并行开发。

## 1. 当前项目基线

目前研究侧已经完成：

- V1 控制标签体系：`form + style + culture`；
- `qijue7 / qilv7` 结构候选识别；
- 《全唐诗》采集与清洗流水线；
- 18,312 首结构候选：七绝 10,369，七律 7,943；
- 1000 首作者/诗体均衡 Gold 候选集：500 七绝 + 500 七律，覆盖 873 位作者；
- Hybrid Style Pre-Annotation V1：规则弱标注 `imagery / density`，LLM 预留 `emotion / diction / expression / energy`；
- 自动结果只写入 `annotation.prelabel`，不直接污染最终 `style`；
- 当前完整测试：41 passed。

当前尚未完成：

- 10 首 LLM semantic-style pilot；
- 人工复核工具与最终 Gold Dataset；
- Dataset / DataLoader；
- Baseline 模型；
- LoRA/QLoRA 训练；
- XLM-R + Style Representation 的正式 Trinity 模型；
- 完整 evaluation pipeline。

## 3. 现在立刻开始的并行任务

### A 线：训练工程骨架

目标：在 Gold Dataset 尚未完成前，先把训练入口准备好，但不得把未经人工审核的 weak label 当 Gold label 使用。

#### A1. 实现 `validate_dataset.py`

至少检查：ID 唯一、form 合法、style 六维完整且枚举合法、emotion 1–2 个、imagery 1–4 个、culture.adaptation 为 null 或 1–5、qijue7/qilv7 基础结构符合约束。

#### A2. 实现 Gold-compatible Dataset Loader

建议文件：

```text
research/src/data/dataset.py
```

第一版只负责：

```text
JSONL
  -> Python record
  -> prompt / control serialization
  -> tokenizer-ready sample
```

先不要加入 XLM-R hidden-state injection。

#### A3. 建立最简单 Baseline 结构

第一版目标不是 Trinity，而是先验证：

```text
FORM + STYLE TEXT CONTROL + poem
            ↓
       Qwen + LoRA
            ↓
      reconstruct/generate
```

必须先跑通：

```text
Dataset -> Tokenizer -> LoRA -> loss -> checkpoint -> generate
```

然后再逐步加入 XLM-R 与 learned style representation。

---

### B 线：Gold 标注与评测

#### B1. 配置 DeepSeek API Key

不要提交 `.env` 或 API Key 到 Git。

先只跑 10 首：

```bash
python -m src.data.preannotate_style --llm
```

默认最多 10 首，不能直接全量运行。

#### B2. 10 首 Semantic Style Annotation Pilot

逐首检查：`emotion` 是否合理；`diction` 是否能稳定区分 plain/refined/ornate；`expression` 是否能稳定区分 direct/balanced/implicit；`energy` 是否与 emotion 混淆；confidence 是否有区分度；evidence 是否真实存在、是否真正支持标签。

输出一份简短记录：

```text
10 首中：
- 完全接受：x
- 小改：x
- 明显错误：x
- 最容易混淆的维度：...
- Prompt 需要修改：...
```

#### B3. 两人共同复核前 30–50 首

两人先独立标注，再比较差异。重点不是“谁对”，而是找标签定义是否存在歧义、哪些维度需要补充判断准则、是否存在需要 multi-label 或 continuous score 的情况。后续可计算 Inter-Annotator Agreement。

## 5. 第一轮 Baseline 之后的模型升级顺序

### Baseline B0

```text
Prompt FORM + STYLE -> Qwen LoRA
```

### Baseline B1

```text
FORM + structured style tokens/prefix -> Qwen LoRA
```

### Model M1

```text
source poem -> XLM-R -> z_sem
style features -> style encoder -> z_style
[z_sem, z_style] -> Qwen adapter/LoRA
```

### Model M2

```text
candidate generation
-> form/prosody scorer
-> reranking
```

### Final cross-cultural stage

加入俄语/韩语源诗与文化适配控制：

```text
culture.adaptation = 1..5
```

## 6. Git 协作规则

当前 milestone 合并到 `main` 后，两个人不要长期直接在 `main` 上并行开发。

建议：

```bash
# Model & Training
git checkout main
git pull
git checkout -b model/baseline-v1

# Data & Evaluation
git checkout main
git pull
git checkout -b data/style-pilot-v1
```

提交建议：

```text
feat(data): ...
feat(model): ...
feat(train): ...
feat(eval): ...
fix(...): ...
test(...): ...
docs: ...
```

每次准备合并前：

```bash
git pull --rebase origin main
pytest tests/ -q
```

原则：

1. API Key、`.env`、模型 checkpoint 不提交；
2. 大型可重建原始语料不提交；
3. 小型 Gold/annotation 版本文件可以提交，必须带版本号和 report；
4. 不覆盖对方尚未提交的本地改动；
5. 标签 schema 一旦修改，两人必须同步确认。

## 7. 实验记录最低要求

每次训练至少记录：

```text
experiment_id
Git commit
数据版本
schema version
base model
seed
learning rate
epoch
batch size / gradient accumulation
LoRA r / alpha / target modules
best checkpoint
train/val loss
semantic metric
form metric
style metric
人工观察
结论
```

不要只保存一个 `final/` 文件夹，否则后续无法解释“哪次实验为什么更好”。
