## 1. 项目一句话

把俄语/韩语诗歌**转写**为符合中文古典格律（七律等）的诗——不逐字翻译，而是保留语义与情感内核，由模型在目标诗体约束下重新创作。可控维度是韦努蒂（Venuti, 1995）**异化 ↔ 归化**的 5 档文化适配强度。

### 3.3 Prompt 设计要点（`PoemService.java`，核心资产）

1. **理论框架**：system prompt 把模型定位为"基于韦努蒂异化/归化理论的转写专家"，而非翻译。
2. **五维度一致性**：强度刻度必须在 ①意象 ②典故/文化负载词 ③句法节奏 ④修辞色彩 ⑤读者体验 五个维度**同时**体现，防止退化为只调意象比例。
3. **逐档指令**（`intensitySpec()`）：1=极端异化（保留白桦/无穷花等源语意象、允许翻译腔）… 3=意象并置互文 … 5=极端归化（白桦→翠竹、无穷花→梅），每档有具体操作定义。
4. **两条不可越过的底线**（任何强度下优先级最高）：
   - 专有名词（人名/地名/朝代/历史事件）忠实音译，绝不本土化替换（"莫斯科"不得变"长安"）；
   - 目标诗体所有硬性形式指标（行数/字数/押韵方案/对仗位置）必须全部满足。
5. **诗体硬约束**（`outputFormName()`）：每种诗体写成可自检的清单，如七律＝8 句×7 字、2/4/6/8 句押平声韵、颔联颈联对仗；时调＝3 行、3-4-3(4) 音步、终章首音步 3 音节转折。
6. **输出前内部自检**：要求模型在输出前逐项核对形式与专名，不合规就重写。
7. **固定输出格式**：`【转写结果】`+`【转写思路】`（策略说明/意象处理/句法修辞/精神内核），前端 PoemCard 依赖该格式分区渲染。

## 4. 链路 B：训练方案（🔜，按 README/立项书规划）

### 4.1 Trinity 架构

```
源诗（俄/韩/中）
  ▼ XLM-RoBERTa-base 冻结 ❄        多语言语义对齐（约 280M 参数，不训练）
  │  取 [CLS] 向量 [B, 768]
  ▼ ProjectionMLP 可训 🔥           768 → 1536，跨模型空间对齐（约 1.5M 参数）
  │  语义前缀 [B, 1, 1536]
  ▼ CultureEmbedding 可训 🔥        文化风格向量表（唐诗/宋词/现代诗…，极少参数）
  │  文化前缀 [B, 1, 1536]
  ▼ 拼接 prefix_embeds [B, 2, 1536] 与 Qwen token 嵌入 concat
  ▼ Qwen2.5-1.5B + LoRA(r=16) 🔥    解码生成中文诗（基座冻结，LoRA 约 7–20M 参数）
  ▼
候选 N 首 → scorer 约束打分重排 → 最优七律
```

**核心思路**：不翻译原文，只提取语义。XLM-R 是多语言模型，俄/韩诗歌的语义向量天然落在中文等价语义附近；因此**只用中文数据训练**（自重构），推理时即可零样本处理俄/韩输入。风格控制不走 Prompt，而是通过 CultureEmbedding 显式注入——这正是立项书"风格控制创新"要验证的点。

### 4.2 训练任务：中文七律自重构

每条样本：输入一首七律（XLM-R 编码）→ 模型重新生成同一首诗。监督信号只作用于诗本身（system/user 位置 label=-100 不计损失）。训练数据 = 开源唐诗七律语料，经 `scorer` 过滤出格律合规的干净子集。

### 4.3 数据流（当前状态标注）

```
docs/*.docx 语料材料                         ✅ 已有（俄3 + 韩17）
  ▼ docx_to_jsonl.py                        ✅ 已实现
research/data/raw/{russian,korean}_samples.jsonl   ✅ 已生成
  ▼ collect_corpus.py（拉取开源唐诗七律）      🔜 待写
research/data/raw/qilu_corpus.jsonl          🔜
  ▼ build_dataset_trinity.py（划分 train/val/test，绑定 culture 标签）🔜
research/data/processed/trinity/*.jsonl      🔜
  ▼ train_trinity.py                         🔜
research/outputs/trinity/{best,final,checkpoint-N}/  🔜
  ▼ generate_trinity.py（候选生成+scorer重排） 🔜
  ▼ 后端新增本地推理通道（与 DeepSeek 并存对比）🔜
```

### 4.4 算力与待定决策

- 可训参数合计约 20–30M，基座与编码器全冻结。**16GB 显存即可**（bf16 + 梯度累积），24G 更稳。
- ⚠️ 尚未确定：用本机/实验室 GPU，还是按预算租云 GPU（AutoDL/恒源云 3090/4090）。此决策影响训练脚本的启动方式，不影响代码结构。
- 评估：量化（格律合规率 via scorer、语义相似度）+ 质性（已有用户问卷），支撑论文与结题。

## 5. research/ 已完成部分详解（✅）

### 5.1 约束打分器 `src/constraints/`（候选重排的核心）


| 文件          | 职责                                                                                                                                                                                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `meter.py`    | 句式检查。`check_form(text, n_lines, n_chars)` 泛化核心；`check_qijue7`（4×7）与 `check_qilv7`（8×7）为薄封装。句数不符 0 分；字数不符按接近程度给部分分                                                                                                             |
| `rhyme.py`    | 押韵检查。`check_qijue7_rhyme`（2/4 句）与通用 `check_rhyme_at_positions`（如七律 2/4/6/8 句）。三种韵模式：`strict`（韵母精确相等）/ `loose`（宽松合并）/ `xinyun`（**中华新韵十四韵**分组，现代读音判韵）；`require_ping=True` 可要求韵脚为平声（普通话一/二声近似） |
| `parallel.py` | 对仗启发式。颔联(3-4)/颈联(5-6)：①同位异字比例（对仗忌同字）②jieba 分词后词数一致时的词性对齐比例；jieba 缺失时优雅降级只算①                                                                                                                                        |
| `scorer.py`   | 加权总分与分发。`score_qijue7`（格律 0.7/押韵 0.3）、`score_qilv7`（格律 0.5/押韵 0.3/对仗 0.2）、`score_poem(text, form)` 统一入口                                                                                                                                    |

已知边界：真实唐诗多按**平水韵**用韵，与普通话分组不完全一致（如杜甫《登高》"哀/回/来/台/杯"平水韵同属十灰，普通话分属新韵"四开/五微"）。`xinyun` 模式对此类诗给部分分而非误判为全错；后续校验真实语料建议引入平水韵韵部表。对仗检查是启发式近似，不能替代人工审校。

### 5.2 语料结构化 `src/data/docx_to_jsonl.py`

把 `docs/` 下两份 docx 转为 JSONL（可重复运行，材料更新后重跑即可）：

- `russian_samples.jsonl`（3 条）：普希金《给娜塔利亚》（1813，汤毓强/陈浣萍译，含 10 条脚注）、《我记得那美妙的一瞬》《致大海》。字段：`id / author / title_zh / year / translator / text_ru / text_zh / notes / source`。
- `korean_samples.jsonl`（17 条）：5 首乡歌（`hyangchal` 吏读原文 + `text_ko` 现代韩文 + `text_zh` 中译三栏）、9 首时调（作者自动提取：周世鹏、禹倬、李兆年、李奎报、元天锡、安边烈等）、1 首辞说时调（黄真伊《青山里》）、2 首现代诗。

### 5.3 测试

`tests/test_constraints.py`：22 个用例，覆盖句数/字数/三种韵模式/平声/对仗/评分分发/历史 bug 回归。真实语料用例：崔颢《黄鹤楼》全绿；杜甫《登高》韵脚部分分 0.5。
